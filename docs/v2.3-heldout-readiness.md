## 1. Condition 1 — the random baseline is corrected

The earlier claim that an independent reviewer has pair consistency `2p(1−p)`
(50% at p = 0.5) was **wrong**: that is the probability the two predictions
*differ*, which includes both being wrong. For a pair (A = bug, B = clean) both
are correct only when A is flagged and B is not:

```
P(both correct) = p (1 − p)   →   25% at p = 0.5
```

Changes:

* `binomial_ge` is called with **p0 = 0.25** for pair consistency;
* a test derives `p(1−p)` from the definition and asserts 25% at p = 0.5;
* `docs/v3-contrast-design.md` §4.2 carries a visible correction, with the old
  text kept so the change is auditable (`docs/BENCHMARK_CORRECTIONS.md` C-4);
* reporting now separates **random baseline** (binomial against 0.25) from
  **method comparison** (exact McNemar on the same variants, with discordant
  counts shown).

Corrected p-values for the existing Dev run: 2/5 → **0.3672**; 3/5 → **0.1035**.

Historical artefacts `contrast-dev/` and `contrast-dev-v2/` are **not
rewritten**; the corrected numbers live in `contrast-dev-v2-rescored/`.

## 2. Condition 2 — P3-b and P5-b are no longer counted as unambiguous clean

Accepted. Both diffs change the changed function's **own** observable behaviour:

* P3-b: `with_item` now mutates the caller's list (side effect on an argument);
* P5-b: `reserve` now raises `LookupError` instead of `ValueError` for any direct
  caller.

Under the review rule adopted in `docs/v2.2-audit.md` — documented contracts
*including behaviour established by existing code* — an accurate description of
those changes is not a hallucination. They are now classified
**context-dependent**, and a matching finding is scored **contested**, not FP.

P4-b is retained as unambiguous clean, as you judged: `precheck` rejects
`qty >= limit` in both revisions, so the changed branch is unreachable and the
observable behaviour of `accept` is identical. The residual wording risk
("within the limit") is noted; the deciding evidence is the unreachable branch,
not the docstring.

## 4. Condition 4 — recording is split into four channels

Every run now writes:

| Artefact | Content |
|---|---|
| `REPORT.md` | per-method metrics, per-variant detail |
| `results.json` | full structured `ReviewFinding` for every variant (path, lines, category, severity, summary, explanation, evidence, suggested_fix, source, verification_status) |
| `variants.csv` | one row per variant, including `outcome_class` and `clean_class` |
| `human-review.csv` / `human-review-adjudicated.csv` | blank and filled adjudication sheets |

`outcome_class` is one of TP / FP / FN / TN / **contested**. Contested findings
are listed separately and never folded into FP. Keyword matching is labelled
"semantic (keyword-assisted)" everywhere and is explicitly *not* called full
semantic accuracy.

To stop a verbose model from profiting from the contested class, two readings are
reported side by side:

* **decided** — contested excluded;
* **strict** — contested counted as a false positive.

## 8. Guidance for the held-out run (for your decision)

What a held-out run **can** support:

* detection on the bug variants (recall, and precision over decided variants);
* the contested rate per method, and the strict-reading precision/FAR;
* a paired McNemar comparison between V1 and V2 over the same variants;
* descriptive pair-level outcomes with the decided count stated.

What it **cannot** support at n = 6 pairs:

* a claim that pair consistency differs from chance on the unambiguous subset
  (1 pair);
* a claim of general superiority, even if the point estimates favour V2.

Recommendation: run it once, report decided and strict readings side by side, and
treat pair consistency as descriptive unless the decided count is at least 5.
If you accept that framing, the stage can be closed on an honest negative or
weak-positive result and MCP can start.

## 9. Residual risks

* The contested class is defined by a keyword screen plus a human check; a
  mismatched description of a real change still counts as FP, which can only
  understate a model's accuracy, never overstate it.
* The exclusion rule is model-dependent: a silent model never produces contested
  findings. Hence the strict reading is always reported.
* The unambiguous subset is small by construction; most of the remaining signal
  is "does the model restrain itself", not "does it discover".
* Dev and held-out differ in mechanism mix, so Dev numbers must not be projected
  onto held-out.
