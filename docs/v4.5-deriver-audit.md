# V4.5 contract-derivation audit — and the false sufficients it produced

Scope: `_signature`, `_changed_definitions`, caller/callee discovery, `_is_dynamic`,
`assess`, as they were at `81ff63c`. Each finding below has a reproducible case in
`docs/v4.5-robustness/`.

## 1. What "contract changed" actually meant

The original detector compared, between base and head, only these:

| Signal | Detected | Comment |
|---|---|---|
| positional/keyword argument names | yes | a new required parameter is caught |
| `*args` / `**kwargs` presence | yes | |
| raised exception names in the body | yes | catches a changed `raise` type |
| return annotation | yes | only when annotated |
| return *AST shape* | yes | `Call` vs `ListComp` counted as a change |
| default parameter values | **no** | `R9-default` |
| decorators / registry membership | **no** | `R10-registry` |
| deleted lines / deleted definitions | **no** | `R2-delete-function`, `R3-delete-file` |
| aliased imports in callers | **no** | `R4-alias` |
| same-named functions in other modules | **no** (name-only match) | `R5-same-name` |
| attribute-chain calls (`self.price`) | partially | `R6-method` matched by bare name |

Three states were conflated: "contract changed", "contract did not change" and
"cannot tell". The third had no representation, so it defaulted to the second — the
unsafe direction.

## 2. False sufficients reproduced before the fix

| Case | Change | Old obligations | Old verdict with the changed file only | Expected |
|---|---|---|---|---|
| `R2-delete-function` | a function is deleted while a module imports it | **none** (no added lines) | `sufficient` | `insufficient` |
| `R9-default` | `announce(value=1)` → `(value=2)` | modified only | `sufficient` | `insufficient` |
| `R10-registry` | a decorated handler stored in a dict | modified only | `sufficient` | `unknown` |

A fourth defect ran the other way: `R8-magnitude` (`return net` → `return net * 3`)
was treated as a contract change because the return *shape* changed, so the gate
over-demanded the caller — a **false insufficient** on a change whose contract is
intact.

## 3. Fixes applied (assessment version `v4.5.2`)

1. **Defaults are part of the signature.** A changed default now counts as a
   contract change, so callers that omit the argument must be read (`R9`).
2. **Return-shape comparison only counts containers.** A container appearing or
   disappearing (`str` → `list`) is a contract change (`H2`); `Name` → `BinOp` is
   not (`R8`), which removes the false insufficient without weakening `H2`.
3. **Deletions are derived.** Definitions whose lines are removed from base are
   recovered from the base AST; if the head no longer has them, their importers
   become `caller_usage` obligations, or an `unknown_dependency` when no importer is
   found (`R2`, `R3`).
4. **Import provenance replaces name matching.** A caller must import the
   definition from the module that defines it (`from .fmt import render`, alias `r`,
   `from .other import render` are distinguished). Same-file bare calls still fall
   back to the plain name (`R4`, `R5`, `R3`).
5. **Dispatch is declared unknown.** A decorated definition, or one stored in a
   module-level mapping, produces an `unknown_dependency` instead of silence
   (`R10`).
6. **Two-hop propagation is declared unknown.** If a caller of a contract-changed
   definition is itself called, an `unknown_dependency` is recorded rather than
   assuming one hop captures everything (`R7`).

## 4. Where "no contract change" is still not proof

Two limits remain, and the gate does not pretend otherwise:

* **Semantic behaviour with identical shape.** `R8` changes magnitude while keeping
  the same signature, return shape and exceptions. The gate says the *coverage* duty
  is the changed definition itself, which is correct for an evidence obligation; it
  makes no claim that the code is right.
* **Aliasing through names that are not imported in the caller's module** (e.g. a
  function passed as an argument from elsewhere) is invisible; the caller simply is
  not found. This is mitigated only by the `unknown_dependency` for decorated and
  registry-dispatched definitions, not by general data-flow analysis.

## 5. Effect on the earlier evaluation

`docs/v4.5-eval/` was re-run with `v4.5.2`: 33 scored profiles, accuracy 100%,
false sufficient 0, false insufficient 0 — unchanged from `v4.5.1`. The fixes above
were driven by the *robustness* set, and did not regress the original set.
